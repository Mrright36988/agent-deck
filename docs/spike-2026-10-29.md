# agent-deck 插件验证报告（2026-10-29）

本文回答一个问题：在 Cursor 插件里运行的 Claude Code 和 Codex 会话，能不能从外部发现、提醒、跳转和作答。下面的结论都来自实测：日志、会话记录和插件代码。没测到的地方会明确写出来。

## 环境

| 项目 | 版本 |
|---|---|
| Claude Code 插件（Cursor 内） | 2.1.312（PATH 上的 CLI 是 2.1.263） |
| Codex 插件 | openai.chatgpt 26.51021，自带 codex 0.164.0-alpha.11.1（PATH 上的 CLI 是 0.154.0） |
| 系统 | macOS（Darwin 25.5），Cursor 同时开着多个窗口 |

## 方法

- 探针 [spike/probe_hook.py](spike/probe_hook.py) 由 [spike/probe_install.py](spike/probe_install.py) 追加到 `~/.claude/settings.json`（6 个事件）和 `~/.codex/hooks.json`（4 个事件）。
- 探针只处理 cwd 在 `spike/probe-ws/` 下的会话，其他会话会在 20ms 内直接放行。
- 遇到需要等待作答的事件，探针等 20 秒后自动作答，用来模拟“用户在 deck 里点了一下”。
- 一共测了两轮。第二轮把选项题的作答点从 PreToolUse 挪到了 PermissionRequest。

## 测出来的约束

1. **Codex 的 hook 必须先信任。** 信任记录按 `文件:事件:组:序号` 存一个 `trusted_hash`，写在 `~/.codex/config.toml` 的 `hooks.state` 下。没信任的 hook 会被静默跳过。用户要在 Codex 插件设置的 Hooks 页手动信任；hook 内容一改，就得重新信任。
2. **agent 改不了 Claude 的全局 hooks。** auto mode 会把写 `~/.claude/settings.json` 判为 Self-Modification 并拒绝，所以安装和卸载只能由用户本人执行。产品的安装器本来就该由用户自己运行。
3. **auto 模式下审批很少。** 测试会话一开始是 auto 模式，`touch` 直接放行了，PermissionRequest 根本没触发。所以“等我”的场景主要是选项题和回合结束。
4. **Codex 的 `notify` 只能配一个**，现在已经被 Codex Computer Use 占用。deck 改用 Codex hooks，不碰 notify。
5. **插件自带二进制，版本会漂移。** Claude 插件装了 2.1.309 到 2.1.312 四个版本；Codex 插件同时跑着两个版本，带的 codex 版本也高于 PATH 上的 CLI。URI、IDE 锁文件、会话注册表这些都没有公开文档，需要做启动自检。

## 结论

- 审批和选项题走 PermissionRequest，两边都能答，谁先答算谁的。deck 要能识别“已经在 Cursor 里答掉了”，并清掉自己的待办卡片。
- Codex 的打字回复走 `codex queue`。
- Claude 的打字回复第一版只做精确跳转，不伪造用户输入。

## 遗留和下一步要测的

- URI 落点：实现阶段再做一次能看得见的测试——先把对应窗口拉到前台，再发 URI，确认 tab 被聚焦、没有分叉。
- Codex 审批在 hook 等待期间插件里是否同时显示审批框；Codex 选项题能不能由 hook 作答。
- Claude 的 http 类型 hook（deck 直接起本地 HTTP 服务接收）在 deck 没运行时，是不是放行而不阻塞（fail-open）。
- 探针卸载：用户执行 `probe_install.py uninstall`。Codex 的 config.toml 里那 4 条探针信任记录可以顺手删掉。
