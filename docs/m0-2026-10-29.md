## 结论和对设计的影响

- **跳转顺序固定为：先按窗口的确切身份拉起窗口，再发 URI**（Claude 用 `open?session=`，Codex 用 `/c/<id>`）。不能直接发 URI，否则会在最后激活的窗口里重复打开会话。
- **窗口身份**：用 `~/.claude/ide/*.lock` 里的 workspaceFolders 去匹配。
  - 单根窗口：拉起用 `cursor <目录>`。
  - 已保存的多根 workspace：拉起用 `cursor <x.code-workspace>`（通过 Cursor workspaceStorage 里的 workspace.json 匹配 folders 找到文件）。
  - **未保存的多根 workspace**（存在 `Cursor/Workspaces/<id>/workspace.json`）：~~`cursor` 命令拉不起来~~（这是没实测的推断，有误：`cursor <这个 workspace.json>` 能拉起，见文末“更正”）。当时的 meeting-copilot 和 devkits 两个窗口都属于这种情况。
- **默认路径不依赖辅助功能。** 找不到确切身份的窗口一律不发 URI，只激活 Cursor 并在 deck 上提示项目名。想让这两个窗口也能精确跳转，有两条路，选一条即可（2026-10-30 更正：不需要，见文末）：
  1. 在 Cursor 里把这两个 workspace 另存为 `.code-workspace` 文件（推荐，一次性）。保存时窗口会重载，要选会话空闲的时候做。
  2. 信任本地签名证书，并给 AgentDeck 开辅助功能权限。agent 执行 `security add-trusted-cert` 会被 auto mode 拦截，只能由用户本人执行。

## 补充：先拉窗口再发 URI 也有竞态（同日 19:37）

用正式的 Jumper 跳到 audio-agent 会话：`cursor <目录>` 执行成功后紧接着发出 URI，结果 meeting-copilot 窗口（window1）新建了面板并发起 `resolve_session_request`，而目标窗口（window9）没有任何聚焦事件。说明 **`cursor` 命令返回时，目标窗口未必已经到了最前**。M0 那次成功只是时机碰巧。

结论：没有辅助功能权限来确认前台窗口，就不发 URI。Jumper 改成只拉起窗口，并提示 tab 名称；之后验证确认，所有窗口都没有新建面板。tab 级的精确跳转留到拿到辅助功能权限之后：发 URI 之前先核对前台窗口。

## 另一个坑：读桌面上的文件会卡住主线程

Jumper 第一次读 `~/Desktop/*.code-workspace` 时，主线程卡在 `Data(contentsOf:)` 上。原因是读桌面这类受 TCC 保护的目录时，会一直等用户回应隐私授权弹窗。修复：单根窗口完全不读 workspace 文件；多根窗口放到后台线程读，并且最后才碰桌面、文稿等受保护的目录；磁盘扫描也整体挪进 actor。

## 修复记录

- app 启动约 1 分钟后崩溃（EXC_BREAKPOINT）。原因是 `@MainActor` 方法里传给 UserNotifications 的回调闭包被推断为主线程隔离，系统却在后台队列调用它，没通过 Swift 6 的隔离检查。已修复：把这些回调显式标成 `@Sendable`。

## 更正：未保存的多根 workspace 也能拉起（2026-10-30）

上文说“`cursor` 命令拉不起来”，这是推断，当时没有实测。

- 源码：Cursor 3.27.14（VS Code 1.128）主进程用 `isWorkspacePath` 判断一个路径是不是 workspace，满足任一条件即可：路径在 `~/Library/Application Support/Cursor/Workspaces/` 下，或扩展名是 `.code-workspace`。所以命令行传入未保存 workspace 的 `workspace.json` 时，它被当作 workspace 解析；已有窗口开着它，就直接聚焦那个窗口。
- 实测：`cursor ".../Workspaces/1789358575156/workspace.json"` 返回 0，meeting-copilot 窗口（原本不在当前桌面）切到前台。Cursor 窗口数前后不变；窗口标题也没变成 workspace.json，说明没被当成文件打开。
- 端到端：Jumper 对这类窗口也改成执行 `cursor <workspace.json>`。用 `agentdeck://diag/jump` 跳到 meeting-copilot 里的会话，deck.log 记录了 `raised .../Workspaces/1789358575156/workspace.json`，目标窗口切到前台，没有新开窗口。
- 同一组文件夹同时匹配到未保存和已保存的 workspace 文件时，优先用未保存的。Cursor 会在窗口关闭时删掉未保存 workspace 的文件：workspaceStorage 里有 50 条这类记录，只有正开着的那 1 个文件还在，所以文件存在基本说明窗口开着。已保存的文件一直留在磁盘上，拉起残留的旧文件会新开一个窗口。
- 跳转仍然只拉起窗口、不发 URI，原因是上文记录的竞态。
- 待查：同一天有一次 `cursor <单根目录>` 返回 0，但窗口没切过去。当时 Chrome 正在新开窗口，并且成了前台 app；重试一次就成功了。原因还没确认。
